# よみもの 2倍の設計（120本 → 239本）

`plan-100.md` の続き。あちらは書き終わり（119本）。ここはその次の120本。

## なぜ足せるのか

書くより先に、**出せる速さ**を測った。

```
いまの予約   2026-10-17 → 2027-02-24 の130日に 47本 = 週2.5本
安全な速さ   週3〜5本（plan-100.md）
```

**下回っている。**週3本に上げるだけで、2027年末までに **135本ぶんの枠**が空く。
120本はそこに収まる。一度に出すのではなく、**日付で薄く延ばす**のは変えない。

## 先に片づけること（これが効率としては一番大きい）

**17本が `【要記入】` で止まっている。**書き終わっていて、日が来ても公開されない。

新しく17本書くより、**17個の質問に一言ずつ答えるほうが速い。**
`python3 tools/build_articles.py` を走らせると、止まっているものが並ぶ。

## 計測が無いまま120本書くことについて

Search Console は 2026-09-14 から動いているが、**まだ一度も見ていない。**
つまりこの120本は、**実際に検索された言葉を見ずに決めている。**

クエリを見れば、どのクラスタが当たっているかが分かる。見てから並べ替えれば、
同じ120本でも**出す順番**が変わる。書く前でなくていいので、どこかで見ること。

## 書き方は変えない

- **「◯◯の原因」は書かない。**「◯◯のとき、何を見て、何を獣医師に伝えるか」
- **一次体験を必ず1つ。**書けないところは `【要記入：質問】` を置く（公開が止まる）
- `seotitle` は必須。**22文字まで**、「犬」「子犬」「老犬」を必ず入れる
- 出口（`cta` / `ctabody`）は記事ごとに書き分ける

### 「症状の伝え方」クラスタだけ、追加の縛り

YMYL のいちばん際どいところ。**次の3つを守る。**

1. **病名を書かない。**「◯◯症の可能性」は一度も書かない
2. **家での処置を勧めない。**吐かせる・薬を塗る・様子を見る日数を決める、はしない
3. **「急ぐ組み合わせ」は必ず入れる。**そのうえで判断は電話の先に渡す

## 出す順番と日付

**週3本を基本**にして、既にある予約の隙間に入れる。日付は書くときに決める。

1. **しつけ・くせ** から。検索量が最大で、いまの119本にほぼ無い
2. **からだ**と**症状の伝え方**。きづく・びょういん の読者がそのまま流れる
3. **からだ**の次に **たのしむ・続ける**。重い話が続かないように挟む
4. **道具**。道具箱の商品が増えたタイミングに合わせる
5. 残り

**季節に縛られるものは無い**ので、Search Console のクエリを見てから並べ替えてよい。
