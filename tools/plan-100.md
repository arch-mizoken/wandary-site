# よみもの 100本の設計

## 方針

**一度に出さない。** 4本 → 100本を一気に公開するのは、Google の
「スケーリングされたコンテンツの不正使用」の典型形で、**ペナルティはドメイン全体**に効く。
LP もサポートページも巻き添えになる。書きためて **週3〜5本ずつ**出す。

**書けるのは「観察と伝え方」まで。** 犬の健康は YMYL に近い領域で、
獣医師でない書き手の断定は、順位でも実害でも損をする。
だから「◯◯の原因」は書かない。**「◯◯のとき、何を見て、何を獣医師に伝えるか」**を書く。
これは Wandary 本体の原則（記録から健康を解釈しない）とも一致する。

**強みは一次体験。** チワワと20年・4匹。競合の記事に無いのはここだけ。
一般論で埋めた記事は価値がない。**自分が実際にやったこと・失敗したこと**を必ず1つ入れる。

**出口を必ず作る。** 各記事の `cta` / `ctabody` は記事ごとに書き分ける。
「記録しておくと、次に困らない」で終わる構造にする。

## 進捗

**書き終わり 79本 / 121本。** 表の ✅ が書き終わったもの。

日付が未来のあいだは公開されない。`.github/workflows/publish.yml` が毎日
00:10 JST に走り、その日が来たものだけを出す。

新しく書いたら、必ず検証してから push すること — 公開は自動なので、
壊れていても誰も見ていない時間に出てしまう:

```
python3 tools/build_articles.py && python3 tools/sitemap.py
```
